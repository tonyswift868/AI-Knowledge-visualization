# 服务器挂了怎么办

先别慌，也不要急着删数据、重建数据库或直接做生产恢复。按下面顺序处理。

1. 记下出问题的时间和你看到的现象，例如“网页打不开”或“任务一直排队”。不要把密码、令牌、学生内容或文档正文贴进记录。
2. 先运行健康检查：`python scripts/mentorflow-enterprise-verify health`。保存它打印出的 JSON receipt 和 evidence 文件路径。
3. 如果只有后台任务卡住，先联系值班人员确认 worker 状态。不要重复提交同一个任务，以免恢复后出现重复处理。
4. 如果整个服务不可用，由值班人员使用已经批准的 incident plan 做故障演练式检查。工具会记录发现故障和恢复所用时间，并在停止服务后尝试把服务重新启动。
5. 数据库或对象文件出问题时，先确认最近一次备份 evidence 是 PASS。恢复测试只能在一次性环境里运行，并且必须带 `--disposable-only`；不要拿生产数据库试。
6. 服务恢复后，再运行 `health` 和 `otel`。确认请求、后台任务、假 Provider、指标和追踪都通过，再逐步恢复正常流量。

需要交给技术人员的内容只有：故障时间、现象、CLI receipt、evidence 路径和是否已恢复。不要发送密码、访问令牌、数据库连接串或用户内容。

如果你不确定下一步，停在当前步骤并联系值班人员。保留数据通常比“赶紧重装”更重要。
