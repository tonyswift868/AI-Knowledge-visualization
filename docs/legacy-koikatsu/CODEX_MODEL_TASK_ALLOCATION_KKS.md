> 工作目录：`E:\aiPlay\AI-Knowledge visualization`

> 目标：把任务按模型独立切片，避免模型间反复接力，降低无效消耗。

## 1. 任务分配总原则

1. 每个任务必须是**完整闭环**：定义范围 -> 实现 -> 验收 -> 报告。
2. 一次只交给**一个模型**执行，不做跨模型接力。
3. 任务结束后停止，不顺手改下一个任务。
4. 用户只负责在任务之间切模型，不允许把同一任务拆成多个模型并行。
5. 优先处理“可确定性验证”的工作，避免主观猜测。

## 2. 4 个模型与默认参数（无复杂度细分）

- `gpt-5.3-codex-spark`：**统一手动设为 High**
- `gpt-5.6-luna`：**统一手动设为 Medium**
- `gpt-5.6-terra`：**统一手动设为 Medium**
- `gpt-5.6-sol`：**统一手动设为 Medium**

说明：任务分配按功能闭环切，不按任务难度拆解，也不依赖推理档位自动切换。

## 3. 模型职责（按功能，不再按“复杂度”切片）

### 3.1 `gpt-5.3-codex-spark`
- 负责：可复现实验、语义约束、契约回归、批量验收脚本、数据报表。
- 适合：明确规则、可自动化验证、以确定性为主的任务。

### 3.2 `gpt-5.6-luna`
- 负责：扫描、索引、批处理、预热、数据覆盖率、资源预算、稳定性修复。
- 适合：脚本化流程和运维化任务。

### 3.3 `gpt-5.6-terra`
- 负责：前端+后端联动的功能闭环、运行时流程、状态系统（可见行为与交互链路）。
- 适合：功能改造、接口联动与用户可见交互。

### 3.4 `gpt-5.6-sol`
- 负责：原生语义对齐、材质/骨骼相关疑难问题、难以归因的错位/兼容性根因（如换卡崩溃、错位边界）。
- 适合：架构判断与深层兼容问题。

## 5. 当前执行建议（你下一步直接采用）

- **第一优先**：`gpt-5.3-codex-spark` 执行 SP-1（不依赖 Sol/ Terra 的猜测）。
- **第二优先**：同模型执行 SP-2（确认契约与边界）。
- **关键链路异常/错位根因明显**：切 `gpt-5.6-sol` 的 SO-2。
- **你要的是“先验可见效果”时**：切 `gpt-5.6-terra` 的 TE-1。
- **资源/扫描/预热**：切 `gpt-5.6-luna`。

## 6. 判定标准（简单版）

- 有可复现脚本/测试。
- 有输入、输出和失败签名。
- 有资源与稳定性边界说明。
- 有未完成项清单。

## 7. 你现在可直接用的命令风格

在每个模型任务开始前：

1. `git status --short`
2. `git diff --stat`（确认只改本任务相关）
3. `git status --short`
4. 运行你设定的任务测试
5. 输出最终格式：
   - 完成清单
   - 失败案例与复现方式
   - 资源指标（CPU/GPU/时间）
   - 下一步建议（只给一个）
