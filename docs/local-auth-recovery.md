# 本地账户恢复与手机号短信边界

MentorFlow 的可选认证部署把“能否找回密码”绑定到已验证手机号：新账号没有默认恢复凭据，必须
在认证部署的账户设置中重新输入当前密码，填写带国家码的 E.164 手机号，并完成短信验证码
验证。未绑定手机号的账号不能找回密码，软件不会用用户名相似度、聊天记录或本地课程
数据替代身份验证。

忘记密码流程如下：

1. 登录页请求验证码。接口无论账号是否存在都返回相同的接受消息，避免账号枚举。
2. 只有已验证手机号的账号会向绑定号码发送 6 位验证码；验证码只保存哈希，10 分钟
   过期，最多尝试 5 次，重发有冷却时间。
3. 输入验证码和新密码后，服务端原子更新密码、消费验证码并撤销该账号全部旧会话。

登录密码错误达到 5 次后，账号会临时锁定 15 分钟；失败次数保存在 SQLite，重启软件
不会绕过限制。成功登录会清零失败次数。

已登录用户可以在“账户与调试”中修改密码。修改前必须重新输入当前密码；服务端会
校验新密码策略、拒绝复用当前密码、撤销其他设备的旧会话，并为当前窗口轮换一个新会话。

纯本地数据模式不需要账号、密码或短信，也不会把这组页面作为学习功能入口。可选认证部署的本地 EXE 不包含短信供应商密钥。真正启用短信需要单独运行的 HTTPS 短信网关，配置
`MENTORFLOW_SMS_GATEWAY_URL`、`MENTORFLOW_SMS_SEND_PATH` 和 Windows Credential Locker
引用 `MENTORFLOW_SMS_CREDENTIAL_REF`。网关接收手机号、用途、验证码和幂等键后再调用
具体供应商；供应商密钥不进入 EXE、SQLite、日志、URL 或聊天消息。

桌面版“账户与调试”页也提供同一配置入口：地址和路径写入本机配置文件，密钥输入后
立即写入 Windows Credential Locker，配置文件只保存 `mfcred_...` 引用。配置完成后
无需把密钥复制到环境变量或项目目录。

因此当前未配置网关时，绑定和发送会明确返回“短信服务尚未配置”，不会假装发送成功。
这不是本地 UI 的限制，而是为了避免把可提取的短信密钥分发给所有软件使用者。

## 账户隔离边界

本地安装的第一个账户负责认领安装包导入的现有学习空间、资料、计划和进度；后续账户
不能再次认领这些空间，只能看到自己创建的空间。保存的创建预设也按账户分目录：第一
个账户继续使用旧预设目录，后续账户自动使用独立目录。客户端传入的预设路径必须落在
当前账户目录内，目录穿越、符号链接和 junction 越界会被拒绝。

这是一台 Windows 电脑上的本地多账户隔离，不等同于云端多租户服务。拥有同一个 Windows
用户配置文件读权限的人仍可能复制 SQLite 数据库和上传文件；如果未来改成在线服务，
还需要在服务端加入每个请求的租户/账户授权、IP 和设备级限流、备份加密以及管理员审计。

## 常见登录隐患与当前处理

- 密码使用 Argon2id 保存，登录失败 5 次后暂时锁定 15 分钟；新注册和重置密码要求至少
  10 个字符并包含三类字符。旧账户如果使用了较弱的历史密码，应在登录后主动更换。
- 登录失败和忘记密码请求使用泛化消息，避免通过响应判断账号是否存在。重置验证码只
  保存哈希，10 分钟过期，最多尝试 5 次，成功后消费并撤销旧会话。
- 短信只能证明当前掌握手机号，不能抵御 SIM 卡更换、号码回收或运营商账户被盗。正式
  在线产品通常还会提供已登录设备管理、备用恢复码、邮件/硬件密钥或人工申诉，并在
  更换手机号时要求重新认证和通知旧设备。
- 本地服务只绑定 `127.0.0.1`；Cookie 使用 HttpOnly 和 SameSite Strict。因为本地回环
  服务没有 HTTPS，Cookie 的 `Secure` 标志不能开启；不能把这个配置直接当作公网服务的
  安全配置。
- 发布版会强制启用登录，即使启动进程的环境变量尝试设置
  `MENTORFLOW_AUTH_REQUIRED=0` 也不会关闭鉴权；免登录只允许带有隔离清单的 UI 评审副本。

手机号找回不需要特殊运营商协议。应用与自有短信网关之间只需要一个 HTTPS JSON 合同；
网关再使用短信供应商的官方 SDK/API、已审核签名和模板。当前应用已经实现验证码状态机，
真正尚未完成的外部条件只有短信供应商账户、签名/模板审核和可访问的 HTTPS 网关。
