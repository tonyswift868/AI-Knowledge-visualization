第二轮：技术栈连环问｜常被问

请求路径

先说请求路径。一句话层。[M03]

MentorFlow 是 Windows 桌面程序，PySide6 建立桌面窗口，Qt WebEngine 显示 React 页面；页面经 QWebChannel（网页与本机程序之间传递请求的桥）把操作交给 Python 本机程序。QWebChannel 把带编号、方法名和参数的请求交给宿主处理器。三句话层。[M03]

像前台把请求交给本机老师处理；实际传递的是受控消息，不是纸单。深一层。[M03]

你可以这样跟面试官说：“PySide6 和 Qt WebEngine 承载 React 页面，页面通过 QWebChannel 把操作交给本机 Python。Python 处理学习业务，再把结果交回界面；桥传递带方法和参数的请求，不让网页直接改数据库。”

常被问｜前端和 Python 怎样接力处理一次操作？

参考要点（先作答，再展开）

  • React 负责显示交互，Python 宿主处理学习业务与本地状态。

  • QWebChannel 把带编号、方法名和参数的请求交给宿主处理器。

  • 宿主返回响应或事件，页面据此更新画面。

资料到回答

再从资料找答案。一句话层。[M06]

本机抽文，文字分批入库。用户选中文件后，客户端在本机抽取文字，切成带页码或章节信息的文本块，再把这些文字块分批送到 Java 服务；原始文件不上传。在 MentorFlow 里，客户端把问题送到 Java 服务找资料，再由客户端把找回的段落连同问题交给模型网关；Java 服务负责查找，不负责生成最终回答。这能让模型回答时多一份可检查的依据，也可能减少凭空发挥；但“给了资料”不等于“答对了”。检索到的段落可能不够，模型也可能读错或答偏。三句话层。[M06]

像跑腿员找出相关讲义交给老师；找到相似段落仍要核对原文。深一层。[M06]

你可以这样跟面试官说：“客户端本机抽取文字，上传文字分块而不是原文件；Java 检索相关片段，客户端再调用模型生成回答。RAG 增加回答依据但不保证正确，引用要回到原文核对。”

  • 这能让模型回答时多一份可检查的依据，也可能减少凭空发挥；但“给了资料”不等于“答对了”。检索到的段落可能不够，模型也可能读错或答偏。

登录与权限

再看登录边界。一句话层。[M08]

身份令牌由资源服务器核对签名和声明；桌面登录服务还会检查它对应的本机进程会话是否仍有效。身份有效后，业务仍要检查账号是否开放、用户是否属于请求的组织或工作区；登录成功不代表有权读取任意空间。三句话层。[M08]

PostgreSQL 和 Keycloak 是两个独立系统，无法由一个 JDBC 事务同时提交或回滚；检查点允许失败后继续原操作。深一层。[M08]

你可以这样跟面试官说：“Keycloak 提供身份凭据，Spring Security 验证进入接口的令牌；业务再检查账号状态和工作区权限。注销还要跨 PostgreSQL 和 Keycloak 分步执行，失败可从检查点继续。”

常被问｜令牌有效是否代表可以读取所有账号数据？

参考要点（先作答，再展开）

  • 原生 access 有效期为 300 秒，刷新后会轮换 refresh；数据库保存刷新令牌摘要和会话主体，不保存刷新令牌明文。

  • 验证令牌后，服务还要检查账号是否开放、用户是否属于请求的组织或工作区；令牌有效本身不代表有权读取任意空间。

  • PostgreSQL 和 Keycloak 是两个独立系统，无法由一个 JDBC 事务同时提交或回滚。

Java 数据库迁移

再看库表权限。一句话层。[M13]

Alembic 迁移仍由专门迁移角色执行，Java 不在启动时自动建表。数据库用行级安全（RLS）按事务绑定的账号/租户范围限制行访问。BUG-107 暴露过线上权限与测试夹具不一致：迁移角色对 account_closure 只有 USAGE、没有 CREATE，所以替换注销函数时报权限错误；修复是在替换函数时临时 SET LOCAL ROLE mentorflow_closure，没有给迁移角色额外授权。三句话层。[M13]

迁移角色能切换到函数属主角色，但不自动继承它的 CREATE 权限，也就是创建数据库对象的权限。深一层。[M13]

你可以这样跟面试官说：“Java 启动时不自动建表，Alembic 仍用专门角色迁移；业务请求按事务范围交给 RLS 限行。曾因线上迁移角色缺 CREATE 失败，我们临时切换已有函数属主角色，不扩大授权，并检查升级结果。”

常被问｜Java 启动、迁移角色和 RLS 各负责什么？

参考要点（先作答，再展开）

  • Alembic 迁移仍由专门迁移角色执行，Java 不在启动时自动建表。

  • 数据库用行级安全（RLS）按事务绑定的账号/租户范围限制行访问。

  • 修复是在替换函数时临时 SET LOCAL ROLE mentorflow_closure，没有给迁移角色额外授权。

同步顺序

先讲同步顺序。一句话层。[M09]

客户端先带着上次保存的游标读取变更；服务器按游标分页返回记录，客户端把远端记录交给本地存储合并，再保存新的游标。接着客户端读取本机待上传队列，优先把记录分批提交；较新的服务器支持批量接口，旧服务返回 404 或 405 时，客户端会退回逐条接口。三句话层。[M09]

如果两台都改同一个字段，就比较字段更新时间；本机和远端的版本信息包含时间与设备编号，时间相同再按设备编号作稳定排序，并提示用户哪份计划的哪些字段各自保留。两台电脑时钟差很大时，按时间判断谁后改可能出错。深一层。[M09]

你可以这样跟面试官说：“一轮先拉服务器变更，再推本机待上传记录。客户端按字段合并，若同一字段两边都改，就按时间和设备编号排序并提示用户；时钟差太大时，先后判断可能不准。”

常被问｜两台设备离线修改时，同步怎样避免整条覆盖？

参考要点（先作答，再展开）

  • 客户端先带着上次保存的游标读取变更；服务器按游标分页返回记录，客户端把远端记录交给本地存储合并，再保存新的游标。

  • 接着客户端读取本机待上传队列，优先把记录分批提交；较新的服务器支持批量接口，旧服务返回 404 或 405 时，客户端会退回逐条接口。

  • 如果两台都改同一个字段，就比较字段更新时间；本机和远端的版本信息包含时间与设备编号，时间相同再按设备编号作稳定排序，并提示用户哪份计划的哪些字段各自保留。

离线覆盖故障

先说失败现象。一句话层。[M11]

我们查到离线修改被同步覆盖，连待上传标记都清掉了。根因是只按服务器版本覆盖整条记录。修成逐字段比较：不同字段各保留，同字段按本地时间和设备编号排序，提示用户。测试用两份独立 Store 互相同步，验证值和队列都没丢；我也会明确说，设备时钟偏差是这个方案的边界。三句话层。[M11]

两台设备时钟差很多时，这个顺序可能不符合实际先后。深一层。[M11]

你可以这样跟面试官说：“离线修改曾被另一台设备覆盖，待上传标记也丢了。原因是整条记录按服务器版本覆盖；改成字段级合并后，不同字段都能留下，同字段按时间和设备号决胜并提示冲突。两份独立 Store 互相同步验证了数据和队列；设备时钟差异仍是边界。”

常被问｜离线修改被覆盖后，你怎样修并验证？

参考要点（先作答，再展开）

  • 我们查到离线修改被同步覆盖，连待上传标记都清掉了。

  • 根因是只按服务器版本覆盖整条记录。

  • 修成逐字段比较：不同字段各保留，同字段按本地时间和设备编号排序，提示用户。

  • 测试用两份独立 Store 互相同步，验证值和队列都没丢；我也会明确说，设备时钟偏差是这个方案的边界。

中断恢复

再说明恢复原则。一句话层。[M12]

数据库已经结算，课堂状态还在检测中，重试就重复结束同一次检测。操作前对照数据库，发现检测已经结束就补完收尾；给每道待答题一个固定编号，再次处理沿用原判定。三句话层。[M12]

测试特意停在两次保存之间，确认恢复后只结算一次；保存失败也必须报错，不能假装成功。深一层。[M12]

你可以这样跟面试官说：“一次检测在数据库结算后、课堂状态保存前中断，重试可能重复记账。恢复先查已经落库的事实，再补完收尾；固定编号保证重复请求沿用原判定。测试在两次保存之间中断，确认只结算一次。”

偶尔问｜进程中断后，怎样避免重复结束一次检测？

参考要点（先作答，再展开）

  • 操作前对照数据库，发现检测已经结束就补完收尾。

  • 给每道待答题一个固定编号，再次处理沿用原判定。

  • 测试特意停在两次保存之间，确认恢复后只结算一次。
