安装与启动：从下载安装包到登录窗口

基线：7df4f6ea。本篇的“偶尔问”是面试复习优先级判断，不是面试频率统计；先读一句话层，再用三句话讲流程，最后挑一处机制或故障深入。[D01]

贯穿全篇的场景是给新同学布置一间学习室：安装器像搬运员，把装备放齐；启动器像门口接待员，先招呼同学，再确认能不能开门；登录窗口像可以坐下来用的学习桌。这个比喻只说明职责和先后关系，不能代替实际程序的验签、文件校验和更新恢复。[I01][I04][I07]

1. 安装器、用户目录与启动入口｜偶尔问

安装器把可运行的 App 和它需要的启动入口放到用户选定的位置，让用户不用手工拼文件就能打开学习软件。[I01] 一句话层。

Inno Setup 是 Windows 安装向导工具，本项目按当前用户安装，默认位置在该用户的本地应用目录，升级时优先沿用已登记的位置。[I02] 安装包带学习 App 和一个负责安装、启动、更新的小助手 UserRuntime；向导把整套待安装文件（payload）与签名清单解到临时目录，再交给小助手预检和安装。[I03] 向导按用户选择建立桌面入口，开始菜单入口也交给这个小助手启动。[I06] 三句话层。

打包脚本确认 App 与 UserRuntime 使用同一发布授权，再验签清单、逐文件核对待安装文件，最后调用 Inno Setup 编出安装程序。[I01] 冻结版的学习数据目录位于安装目录的 Data 子目录，签名 App 文件与学习数据分开放。[I04] 安装核心先核对暂存文件，再切换目录；新窗口可见且响应才记为健康状态 HEALTHY，失败则走恢复路径。[I05] 深一层。

搬运员先把学习室装备放齐，接待员再确认学习桌能用，能帮助记住“先安装、再确认启动”。但实际签名和文件校验是程序执行的检查，不是看看箱子外观就算验收。[I01][I05]

你可以这样跟面试官说：“我用 Inno 做安装向导，把整套程序交给随包的安装和更新助手处理。它先验清单和暂存文件，再换入 App，确认新窗口可见、能响应才算安装成功。学习数据单独放在 Data，和要替换的程序文件分开。”[I01][I02][I03][I04][I05]

安装程序和 UserRuntime 各负责什么？

  • 参考要点：安装器把可运行的 App 和它需要的启动入口放到用户选定的位置，让用户不用手工拼文件就能打开学习软件。
  • 参考要点：安装包带学习 App 和一个负责安装、启动、更新的小助手 UserRuntime；向导把整套待安装文件（payload）与签名清单解到临时目录，再交给小助手预检和安装。
  • 参考要点：安装核心先核对暂存文件，再切换目录；新窗口可见且响应才记为健康状态 HEALTHY，失败则走恢复路径。

2. 启动器先反馈，完整校验在后台｜偶尔问

桌面和开始菜单快捷方式指向 Updater\UserRuntime.exe launch，先启动的是负责安装状态和更新恢复的 UserRuntime，不是直接启动学习 App。[I06] 一句话层。

UserRuntime 在加载 Qt 或启动监视窗口前先画出“正在启动…”小窗；随后在后台串行检查安装事务、恢复中断状态，并确认签名版本里的关键启动文件存在。[I07] 如果发现已经下载好、尚未安装的版本，启动器会在运行 App 前尝试完成安装；失败原因记入启动维护日志，恢复后是否继续打开取决于当前版本是否仍被判定为健康。[I08] 三句话层。

学习 App 先确认已验签清单列出的关键启动文件存在，再显示登录窗口；核对整套程序目录的工作放到低优先级后台线程。[I09] 同一已验证版本的 App 目录中，文件大小和时间等状态未变就跳过重算指纹；状态改变的文件重新算 SHA-256，新版本或校验记录缺失时则全部重算。[I09] 安装、更新写入新文件时仍逐个校验，后台发现损坏会提示修复，不自动关闭学习窗口。[I10] 深一层。

接待员先招呼同学，再查有没有上次没完成的装备更换；同学坐到学习桌前后，后台继续盘点。这只类比先有反馈、再做重活，不能理解成取消验签或不检查文件。[I07][I08][I09][I10]

你可以这样跟面试官说：“用户点的是启动器快捷方式。它先显示启动提示，再检查有没有上次更新留下的事务；有待安装版本就先尝试恢复，没有的话才拉起 App。App 先做很小的启动文件检查并显示登录窗，完整文件校验在后台跑。这样安全检查还在，但不会让整包哈希挡在登录窗前面。”[I06][I07][I08][I09][I10]

3. 登录窗的响应、绘制与验证｜偶尔问

健康握手要确认新 App 的登录窗口已经可见、能响应，而不是只确认进程存在。[I11] 一句话层。

账号外壳先创建并显示登录窗，里面可以继续准备页面。[I12] 更新检查在这里后台开始，表单能填，提交登录要等检查结果。[I12] 检查失败或等待上限到期时，只按本机已验签的策略决定能不能继续，已有强制更新仍拦登录。[I13] 三句话层。

闪烁曾是绘制方式变化造成的：Qt 是桌面窗口框架，网页使用的 OpenGL 是一种图形绘制方式；登录窗显示后才加入这类控件，Qt 重建了顶层窗口。[I14] 现在窗口第一次显示前就带一个常驻的小绘图控件，注册页也在同一个窗体里准备，避免中途切换窗口绘制方式。[I14] 启动日志分别记录进程启动、Qt 就绪、登录窗显示和可输入几个阶段，便于复核不同入口的耗时。[I15] 闪烁修复则用连续截图和窗口隐藏、显示事件来验证。[I15] 深一层。

接待员让同学先坐到桌前，学习室内部继续准备，像先显示登录窗、再完成后台工作。但普通桌子不会因更换图形绘制方式重建，这只是说明先后关系；真实闪烁原因要看 Qt 窗口的绘制表面和隐藏、显示日志。[I12][I14][I15]

你可以这样跟面试官说：“我把窗口出现、能响应、登录条件就绪分开看：健康握手确认目标窗口可见并响应，日志记录各段耗时，连续截图和窗口事件检查有没有闪烁。那个闪窗问题是显示后才改变绘制方式，我们在窗口第一次显示前就准备好图形控件，注册页只切内部页面。”[I11][I14][I15]

怎么证明登录窗快而且不闪？

  • 参考要点：健康握手要确认新 App 的登录窗口已经可见、能响应，而不是只确认进程存在。
  • 参考要点：启动日志分别记录进程启动、Qt 就绪、登录窗显示和可输入几个阶段，便于复核不同入口的耗时。
  • 参考要点：闪烁修复则用连续截图和窗口隐藏、显示事件来验证。

学习路线：不用背｜基本不问

不背 Inno 页面坐标、每个启动日志事件名、启动状态文件名、版本号和检查函数名；能讲清用户级安装位置、快捷方式为什么先走 UserRuntime、完整校验为什么挪到登录窗后，以及用窗口可见性和分段日志怎样验证启动体验即可。[I02][I06][I09][I11][I15]
