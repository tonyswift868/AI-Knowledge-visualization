专题：从一摞资料到一张能照着学的计划

事实基线：7df4f6ea。本篇按当前项目代码和需求状态说明；“常被问／偶尔问／基本不问”是面试复习优先级，不是面试频率统计。[P01]

想象你要替朋友安排一门“从没下过厨，到能独立做一道菜”的短课：先问他想做到什么、现在会什么、哪天有空；再挑菜谱；然后把章节排成课；最后把每次练习放进日历。这个比喻帮助理解计划流程，不表示软件真的在教做菜，也不表示 AI 可以凭空编菜谱。[P01]

1. 先问清楚想学到哪里｜常被问

先定目标，再排计划。

计划先问清楚学什么、学到什么程度，以及能投入多少时间。表单收集学习目标、最终目标、当前水平、开始和结束日期、每天上限、每周可学日、特殊日期和补充说明；程序校验必填内容、日期和权重，格式不合就要求修正。[P02] 一句话层。

像给朋友排厨艺课，先问想做什么菜、现在会哪些刀工、哪天能来。AI 帮忙理解补充要求、追问缺少的信息，并给一份需求摘要和大致模块。用户确认前，不直接生成完整知识地图；本机控制流程的程序按阶段执行，付费生成和开始计划也由用户点按钮确认。[P03] 三句话层。

这和“一句话让模型一次做完整个课表”不同：先有需求摘要，再有粗略模块；用户确认方向后才进入资料选择，之后再看按资料整理的结构。[P03] 深一层。

为什么不直接让 AI 一次生成完整计划？

  • 表单收集学习目标、最终目标、当前水平、开始和结束日期、每天上限、每周可学日、特殊日期和补充说明；程序校验必填内容、日期和权重，格式不合就要求修正。[P02]
  • AI 帮忙理解补充要求、追问缺少的信息，并给一份需求摘要和大致模块。[P03]
  • 用户确认前，不直接生成完整知识地图；本机控制流程的程序按阶段执行，付费生成和开始计划也由用户点按钮确认。[P03]

学习路线：你可以这样跟面试官说

我会先把目标、基础和时间约束问清，再让用户确认学习方向。AI 帮忙理解和整理，程序控制流程并校验输入，不会把一条模糊指令直接变成整份计划。[P02,P03]

2. 先挑完整资料，再把正文请进来｜常被问

推荐候选，采用才读。

推荐资料只是候选，不代表正文已读取或覆盖已确认。AI 推荐完整资料，例如教材、课程、完整文档或 GitHub 文字仓库；它给出名称、链接、简短理由和大致覆盖模块。[P04] 一句话层。

朋友挑菜谱时可以用自己带来的书，也可以从推荐书单里选。用户上传文件、贴网址或给 GitHub 仓库后，资料进入本机计划。被采用的网页或文件再被读取、抽出正文并切成带章节位置的文字块，后面的知识地图从这些已采用的文字块出发。[P05] 三句话层。

用户自己的资料默认采用；推荐资料由用户选择后读取。用户采用后，资料才加入计划用于教学；读取失败会显示原因，不会把“推荐了”说成“已读完”。[P06] 深一层。

用户点了“采用”，是不是代表程序已经确认这份资料适合学习？

  • AI 推荐完整资料，例如教材、课程、完整文档或 GitHub 文字仓库；它给出名称、链接、简短理由和大致覆盖模块。[P04]
  • 用户上传文件、贴网址或给 GitHub 仓库后，资料进入本机计划。[P05]
  • 用户自己的资料默认采用；推荐资料由用户选择后读取。[P06]

学习路线：你可以这样跟面试官说

资料推荐只是候选。用户选中后，程序才读取正文并保存章节和文字块；自己的资料按产品规则默认采用。这样知识地图有实际原文可追，而不是按资料标题猜课程内容。[P04,P05,P06]

4. 知识结构与参考资料的分工｜常被问

正文成课，导航作参考。

资料目录不是课程本身，书单和路线可留作导航，不必变成要讲、要考的知识点。[P09] 一句话层。

书单、学习路线和资料取舍可以放在模块开头当“资料导航”，而不变成要讲、要考、要记时长的知识点。[P09]

这像把菜谱书的“推荐书目”放到课前参考架，而不是安排成一节“学习书单”。明确是书单或路线的章节先由程序识别；看不清用途的章节，AI 按给定段落把每段标成“知识”或“导航”。程序核对段落编号没有遗漏或重复，再根据原文标题层级生成知识结构和出处。[P10] 三句话层。

用户定的是大知识点按主题组织，大小由主题决定，不设上下限、不按字数或分钟机械切；这一要求目前落实在已有计划的主题重组流程中，模型提议分组、程序检查覆盖。新建计划的目录流程仍从原文层级构造初始结构。两条路径不同；重组后小要点可能换父点并重新编号。[P11] 深一层。

新式知识点里，大点有若干小要点；每条讲义摘句带着对应原文出处，原文仍可点开。若资料本身没有知识正文、只有导航内容，计划不会用导航硬凑出一门课。[P12]

5. 估时不是拍脑袋，日历也不是番茄钟｜常被问

程序估时，按权重排日。

时长从学习内容和检测需求估算，再按可学日排进计划，不是先拍个总数。[P13,P14] 一句话层。

像把菜谱步骤、练习和可上课的日期放进日历。旧式知识点估算可参考原文长度、题量与难度标记，由程序计算分钟数；AI 不直接决定分钟数。新式知识点初建时，小要点分钟由程序按原文量和默认难度计算，大点总时长等于小要点之和；当前新建路径不另跑一次 AI 难度评估。[P13] 三句话层。

计划把分钟数按可学日分配，周几不学可设为 0，半天可设为 0.5，特殊日也能覆盖周安排。没完成的分钟变成待还，后来学习先补欠账；学多了显示超前。用户可以调整日期、每日上限或内容。[P14] 深一层。

谁来估时，漏学之后怎么办？

  • 新式知识点初建时，小要点分钟由程序按原文量和默认难度计算，大点总时长等于小要点之和；当前新建路径不另跑一次 AI 难度评估。[P13]
  • 周几不学可设为 0，半天可设为 0.5，特殊日也能覆盖周安排。[P14]
  • 没完成的分钟变成待还，后来学习先补欠账；学多了显示超前。[P14]

时长估算有明确输入：原文、题目和难度；程序负责计算与日历分配。学习进度不足会显示待还，后面先补欠账，用户决定是否重排，不会暗中改掉计划。[P13,P14]

6. 提示词和上下文：把当前资料交给 AI，把流程留给程序｜常被问

任务清楚，资料可核。

提示词就是给 AI 的任务说明；上下文是这次要看的原文、目标和相关资料。请求只带完成当前任务所需的内容和明确编号，不把整本书塞进去。目录分类请求以章节 ID、标题和段落为输入；知识点讲义请求只带相关知识点、小要点及其出处段落。[P15] 一句话层。

像给助教本周菜谱和今天要做的一步，而不是搬来整座图书馆。对用途含混的章节，AI 按批次把给定段落标成“知识”或“导航”。程序检查编号覆盖没有遗漏或重复。讲义生成也按小批次提供对应原文，返回内容要能在原文里核实。[P15] 三句话层。

这些请求不是让 AI 自由发挥：分类器拿到章节 ID、标题和原文段落；讲义请求只带点与小要点的 ID 以及引用段落。有效讲义必须是对应段落中的原文摘句，并通过来源校验；失败的摘句只在其批次内重试。[P15]

“前缀”就是请求开头的内容；缓存是复用此前完全相同的开头。项目的请求布局缓存是进程内、有界、按相同系统提示和前缀追加历史；它不是持久学习记录，也不保证每次命中。[P16] 深一层。

如何让 AI 看材料，但不把系统流程交给它？

  • 目录分类请求以章节 ID、标题和段落为输入；知识点讲义请求只带相关知识点、小要点及其出处段落。[P15]
  • 程序检查编号覆盖没有遗漏或重复。[P15]
  • 有效讲义必须是对应段落中的原文摘句，并通过来源校验；失败的摘句只在其批次内重试。[P15]
  • “前缀”就是请求开头的内容；缓存是复用此前完全相同的开头。[P16]
  • 项目的请求布局缓存是进程内、有界、按相同系统提示和前缀追加历史；它不是持久学习记录，也不保证每次命中。[P16]

学习路线：你可以这样跟面试官说

AI 只处理本次要看的段落和清楚的任务；程序检查编号、原文出处与流程状态。把稳定内容放前面能争取缓存复用，但命中与否要看实际请求。[P15,P16,P17]
