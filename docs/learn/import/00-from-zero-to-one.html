先把学习做顺。

用户说，做 MentorFlow 是为了方便用 AI 学东西，比如项目上要用的知识。7 月最早的“学习远征”是学东西攒货币、再用货币玩的玩法；后来觉得不好做、也没必要，于是只专注学习业务。9 月 29 日，严重 bug 堆在一起，用户几乎不想做下去，便推倒旧代码重来。今天这套系统，就是围绕“依据资料学准”逐步接起来的桌面 AI 教师平台。[C01]

以下按搭建一间自习室来理解：先有房间和桌椅，再备本地账本、课程、老师、门禁、分馆、装修和资料柜。这个比喻帮助记住分工；软件没有真的房间，数据与控制也不是家具。

第一站：先搭桌面窗口｜偶尔问

窗口把学习功能放在一处。一句话层。[C02]

MentorFlow 是 Windows 桌面程序，PySide6 建立桌面窗口，Qt WebEngine 显示 React 页面；页面经 QWebChannel 把操作交给 Python 宿主。宿主管学习流程，界面负责呈现和交互；用户点“开始”后由宿主处理，而不是让网页直接改数据库。像自习室先有房间、白板和管理员，但程序的桥不等于房间里的任何页面都能接管账本。三句话层。[C02,C03]

你可以这样跟面试官说：“它是 Windows 桌面学习软件：PySide6 和 Qt WebEngine 承载 React 界面，页面通过桥调用 Python 宿主。界面展示操作，宿主处理流程和本地数据。”

页面怎样把操作交给程序？

  • 参考要点：PySide6 建立桌面窗口，Qt WebEngine 显示 React 页面。
  • 参考要点：页面经 QWebChannel 把操作交给 Python 宿主。
  • 参考要点：宿主管学习流程，界面负责呈现和交互。

第六站：多台设备接续学习｜常被问

本地记账，异地接续学习。一句话层。[C12]

学习变化先写入本地待同步队列，登录和定时同步时再与服务器交换账号记录；失败项目留在队列等待重试。客户端 CourseStore.apply_remote 接收远端记录，并将其与尚未同步的本地改动按字段合并，避免把整份新旧数据盲目覆盖。像两家分馆交接借阅登记，但原始上传文件留在本机，服务器同步记录不等于备份原件。三句话层。[C12,C13]

你可以这样跟面试官说：“客户端先保存本地变化，再把账号记录放进待同步队列；同步失败会保留待处理项。客户端接收远端记录时按字段合并尚未同步的本地改动，用户上传的原始文件不随账号同步。”

同步为什么不等于备份？

  • 参考要点：学习变化先写入本地待同步队列。
  • 参考要点：客户端 CourseStore.apply_remote 接收远端记录，并将其与尚未同步的本地改动按字段合并。
  • 参考要点：原始上传文件留在本机，服务器同步记录不等于备份原件。

找到资料为什么不等于答对？

  • 参考要点：客户端抽取本地资料文字并发送文本块。
