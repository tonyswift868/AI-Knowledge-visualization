# MentorFlow — 需求与当前状态

唯一的需求与状态文档。使用规则见 [AGENTS.md](../../AGENTS.md)「需求文档规则」：先查索引，按编号检索条目；一条事实只写一处；冲突原位替换；状态如实分级；索引与条目同步。

## 文档维护规则（用户 2026-10-10 定，最优先）

- 每个条目是一个固定的“状态位”：只写现在的规则、现在的状态和还没做完的事。新决定、新发现当场改写对应条目，不往后追加新段落。
- 过时的说法、已经被取代的方案、试验和讨论过程，一律直接删除（过程在 git 历史里），不保留“原为…”“旧做法…”。
- 验收清单和待办做完就删掉那一行，把位置让出来（“吃完饭的桌子要收拾，不是再摆新桌子”）；同时推进的多项可以并存。
- BUG 条目是真实发生过的问题记录（以后写简历、对外讲要用：当时数据、怎么查、怎么优化、结果），永久保留；解决后状态写“已关闭”，同类问题再出现时在原条目里更新。
- 上线、发版、用户实测中发现的问题，发现当场就记 BUG 条目（还没修的写“待修”），不只写在验收清单或任务里；验收清单只写要求和 BUG 编号（用户 2026-10-11 定）。
- 发现文档和代码或用户说法不一致时，当场纠正，不等整理时才看。

## 工作准则（用户 2026-10-05 定）

- 出了问题先和用户讨论清楚：现象、原因、牵连范围，再谈怎么改；不出看着笃定但有漏洞的方案。
- 能并行、互不冲突的改动一次派完；有前置依赖的说清先后与原因。
- 每份任务第一节写“用的现成项目与许可证”，不重复造轮子，参照行业标准做法。
- 不懂或感觉和用户意思有偏差，直接问用户，不猜。

### [DIR-01] 产品方向：AI 只找资料，不出题、不判主观题
- 状态：已实现（第三十七至七十三批），用户正式测试中。
- 来由：最初设想 AI 自己找资料、出题、判题；实测 AI 不稳定、成本高，出的题和判的分都不可信（用户 2026-10-03、10-06 定）。
- 规则：
  - AI 只负责找资料，以及在资料里“找、指出、配对”（例如指出知识点依据哪一段、问答题要点选哪几条、知识点之间的前置关系）。AI 不出题、不解题、不写答案、不判主观题。
  - 题目只来自资料自带的题，或用户自己上传的题。资料没题的模块只学不考；有题的按题考核（[TEACH-02]、[CHK-01]）。
  - 老师照资料原文讲，可以用自己的能力打比方、举生活化的例子，但不能推出原文没有的结论；不讲资料里没有的知识点。
  - 用户自己上传的资料、贴的网址和 GitHub 仓库一律当可信资料，照着教，不筛选。
- 关联：[PLAN-06] [TEACH-02] [TEACH-04] [CHK-01]
- 更新：2026-10-10

### [ARCH-06] 新建计划的流程
- 状态：已实现；用户用 JavaGuide 走过一轮。
- 流程：
  1. 表单：学习目标、最终目标、起止日期、每天最多学多久、每周哪几天能学、特殊日、当前水平、是否只用自己的资料。
  2. 多轮对话聊清需求：每轮一两个问题、轮数不限，用户可随时说“直接开始”；对话里的改表单、限定范围、删模块等由意图理解处理，付费和开始仍需点按钮。
  3. 给“需求摘要 + 大致模块”（只列模块名和一句话），用户同意后进入资料。
  4. 资料（[PLAN-06]）：AI 推荐 3～5 份完整资料的链接，用户自己选，下载上传或贴网址/GitHub 仓库；用户自己的资料默认采用。
  5. 按资料定结构：显示简略结构树（只有模块和连线，可拖动缩放、点开看依据章节），标出资料没讲到的目标；和学习无关的内容（导航、求职这类）单列排除、不进模块。
  6. 确认后按模块并行填知识点（每点标依据第几段，原文由程序按编号显示），生成知识地图；可用对话或面板删模块、删知识点，由程序本地删除、不重新生成。
  7. 估时与超限提醒见 [PLAN-05]；点“开始计划”后进入进行中，第 1 模块备好题即可开课（[TEACH-08]）。
- 当前实现：app/plan_flow.py、course/planner_agents.py、plan_intent.py、research_pipeline.py、source_quality.py；页面 web/src/pages/NewPlan.tsx。
- 关联：[PLAN-01] [PLAN-02] [PLAN-04] [PLAN-05] [PLAN-06]

### [BUG-03] DeepSeek 用量口径错误：缓存命中多时回答被判无效、用量少算
- 状态：已关闭（2026-09-27）
- 现象：新建计划时“按意见修改路线轮廓”连续失败，提示“模型没有返回有效的完整协议响应”；日志里一次“测试连接”也同样失败。
