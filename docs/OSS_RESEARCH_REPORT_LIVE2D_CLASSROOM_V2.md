This is a selection record, not an approval to copy assets. Code licenses and model/theme/media licenses are assessed independently. No model, motion, texture, sound, or background was downloaded into the product from the research checkouts.

## Evidence and policy

- Every commit below is the checked-out `HEAD` in the research directory. The commit link is immutable and is the version to review.
- `motion-ui` explicitly excludes the Hiyori model and says its screenshot/model are Live2D sample data; its MIT license covers the repository's HTML, scripts, and documentation only.
- `pixi-live2d-display` includes Live2D test models and motions under the upstream test tree. Those files are treated as Live2D sample data, not as MIT code.
- `CubismWebFramework` and `CubismWebSamples` state that framework code is under Live2D Open Software License, Cubism Core is under the proprietary license, and sample models require the Free Material License and model-specific terms. Business use can require a Cubism SDK Release License.
- `Open-LLM-VTuber` is MIT for its application code but has a separate `LICENSE-Live2D.md`; its bundled Live2D sample models and motions are not MIT. Its background directory has no per-file license receipt.
- The current local Tsubaki archive has a “use notice” but no redistribution license. It is therefore private/local-only and a public-release blocker.
- A repository-level MIT/Apache license never changes the license of an included model, motion, texture, sound, font, or other artwork.

## Current baseline decision

`untitled-pixi-live2d-engine` **1.3.5** is already pinned in `frontend/package.json` and `frontend/package-lock.json` (npm integrity `sha512-F9X54p9X6tUT6bgjp8fXaf3QRPRvLurNVXn8De0XvsW1aUCvCuK8z0+Q3iiIgT+TeLnhYWQ2HjjROQy51U7PzQ==`). Its package metadata says MIT, author GuangChen2333, PixiJS `^8.13.1`, and Cubism 2/3/4/5 support. It is the only Live2D web runtime to retain for this phase. The MIT code license does **not** grant rights to the Cubism Core binary or any model/motion asset.

The current direct teacher-runtime packages are pinned in the manifest as well: PixiJS 8.13.1 (MIT), `three` 0.180.0 (MIT), `three-stdlib` 2.36.0 (MIT), `@pixiv/three-vrm` 3.4.0 (MIT), and `@esotericsoftware/spine-player` 4.1.54 (Spine Runtimes License, not MIT). No Spine or VRM character asset is currently bundled under `frontend/public/teacher2d`; a future model pack requires its own asset receipt.

## Adoption gates

1. Keep semantic teacher actions on native motion, expression, or parameter animation. Whole-model `translate`, `scale`, `skew`, or rotation may only be stage/camera placement and must not be presented as teacher motion.
2. Before a public build, remove or exclude the private Tsubaki subtree and the Live2D Core binary unless the original author/Live2D license explicitly permits redistribution. `MentorFlow.spec` already omits Tsubaki from public builds by default.
3. Do not copy Hiyori/Mao/Shizuku or any other Live2D sample model/motion from the research checkouts. The official sample terms and notices must be accepted and recorded separately if a future test-only fixture is introduced.
4. Preserve each adopted code license and commit in `docs/THIRD_PARTY_ASSET_MANIFEST.json`; pin remote dependencies and do not use CDN-loaded runtime code in releases.
5. Any unknown source, author, integrity, or commercial/redistribution condition is a blocker, not an inferred permission.
